The SimuMarket AI HTTP API uses the `/v1` prefix. The OpenAPI schema exported from FastAPI is the reference for endpoints and schemas on this site. The base URL depends on the deployment environment.

## Conventions

| Area | Shape |
|---|---|
| Content type | `application/json`, except SSE and direct uploads to object storage |
| Money | Integer IDR, for example `49000`, never `49000.0` |
| Time | ISO 8601 in UTC |
| Resource IDs | UUID |
| Authentication | Access and refresh tokens in `HttpOnly` cookies |
| Correlation | `X-Correlation-ID` for tracing a request |
| Create retries | `Idempotency-Key` on operations that support retry |

Browsers must send cookie credentials on cross-origin requests. Tokens are not kept in `localStorage`. Refresh tokens rotate after a successful refresh, and the previous value cannot be reused.

## Business scope and RBAC

A role belongs to a user and business membership, not to a user globally. `owner` manages the business profile, products, members, analyses, and reports. `cashier` can only read active products and record transactions in the business they belong to. Resources from another tenant return `404` so their existence does not leak.

Endpoints that operate in a business context accept `business_id` in the query or body according to the schema. Every receipt import endpoint takes `business_id` as a query parameter at each step, including create, complete upload, read, edit draft, and confirm.

## Asynchronous processing

Analysis, OCR, and export do not finish within the initial request. The create endpoint returns a queued resource, and the client reads the status until it is terminal.

| Terminal value | Meaning |
|---|---|
| `completed` | Every planned component succeeded |
| `partial` | The deterministic part is available, another component is not. Neither a failure nor a full success |
| `failed` | The run produced no usable report |
| `cancelled` | The run was stopped before completion |

The `simulating` stage can be removed from the plan when a deployment has no agent adapter at all. A removed stage is reported as skipped rather than credited as completed work, so the progress percentage never describes work that did not happen.

### SSE and the polling fallback

The analysis events endpoint emits events named `status`. Every transition is persisted to PostgreSQL before publication; Redis is only transport.

```text
id: 4
event: status
data: {"schema_version":"analysis-event-v1","event_id":"4","status":"simulating",
       "current_stage":"simulating","completed_stages":["queued","collecting_evidence",
       "building_context"],"skipped_stages":[],"percent":45,
       "message":"Panel persona sedang mengevaluasi skenario","warnings":[],
       "failure_code":null,"correlation_id":"...","occurred_at":"2026-08-15T08:01:20Z"}
```

Client rules:

- keep the last `event_id` and send it as `Last-Event-ID` when reconnecting; the server resumes from the next sequence without replaying old events;
- `event_id` increases monotonically per analysis;
- `failure_code` is `null` on a normal run and carries a safe code on terminal failure;
- do not infer the cause of failure from the order of `warnings`;
- if the stream keeps dropping, poll the resource status snapshot every three seconds. The snapshot reads current state directly, so it is not compared against `event_id`.

The progress percentage comes from the weighted stage completion the backend sends. Clients do not compute it.

## Idempotency

| Operation | Mechanism |
|---|---|
| Create analysis | `Idempotency-Key` header, unique per user |
| Create transaction | Optional `client_reference`, unique per business when set |
| Confirm receipt import | Re-confirmation returns the same transaction |
| Create export | Idempotency key on artifact creation |

The goal is the same in every case: a request sent twice through a double click, a reconnect, or a network retry must not produce two records.

## Error shape

```json
{
  "error": {
    "code": "ANALYSIS_INPUT_INCOMPLETE",
    "message": "Data biaya variabel diperlukan untuk menghitung BEP.",
    "fields": [{"path": "pricing.variable_cost_per_unit_idr", "reason": "required"}],
    "correlation_id": "uuid",
    "retryable": false
  }
}
```

| Field | Purpose |
|---|---|
| `code` | A stable, machine-readable code |
| `message` | An Indonesian message safe to display |
| `fields` | Per-field detail when the error is a validation error |
| `correlation_id` | The link to logs and traces when a user reports a problem |
| `retryable` | Determines whether a retry button makes sense |

Error responses never contain a stack trace, a prompt, or a raw provider response. `409 EDUCATION_PREREQUISITE_NOT_MET` means a required module is incomplete, not that the server failed.

A `partial` status is a legitimate outcome, not an error. Clients show the server's warnings and limitations without filling in missing values or presenting the run as a success.

The [endpoint reference](./referensi) is generated from the backend OpenAPI snapshot, so it contains exactly the endpoints that genuinely exist. The interactive playground is disabled in the public documentation so an example cannot accidentally send a request to a production environment.
