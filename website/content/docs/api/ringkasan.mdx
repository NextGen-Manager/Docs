API HTTP SimuMarket AI memakai prefix `/v1`. Skema OpenAPI yang diekspor dari FastAPI menjadi sumber referensi endpoint dan schema di website ini. Base URL bergantung pada environment deployment.

## Konvensi

| Area | Bentuk |
|---|---|
| Content type | `application/json`, kecuali SSE dan upload langsung ke object storage |
| Uang | Integer IDR, misalnya `49000`, bukan `49000.0` |
| Waktu | ISO 8601 dalam UTC |
| Resource ID | UUID |
| Authentication | Access dan refresh token melalui cookie `HttpOnly` |
| Correlation | `X-Correlation-ID` untuk menelusuri request |
| Retry create | `Idempotency-Key` pada operasi yang mendukung retry |

Browser harus mengirim credential cookie pada request lintas origin. Token tidak disimpan di `localStorage`. Refresh token dirotasi setelah refresh berhasil dan versi lama tidak dapat dipakai kembali.

## Ruang lingkup usaha dan RBAC

Role melekat pada membership user dan usaha, bukan pada user secara global. `owner` mengelola profil usaha, produk, anggota, analysis, dan report. `cashier` hanya dapat membaca produk aktif dan mencatat transaksi pada usaha tempatnya menjadi anggota. Resource dari tenant lain dikembalikan sebagai `404` agar keberadaannya tidak bocor.

Endpoint yang bekerja dalam konteks usaha menerima `business_id` melalui query atau body sesuai schema. Seluruh endpoint receipt import memakai query `business_id` pada setiap langkah, termasuk create, complete upload, read, edit draft, dan confirm.

## Pemrosesan asinkron

Analysis, OCR, dan export tidak selesai pada request awal. Create endpoint mengembalikan resource berstatus antre, lalu client membaca status sampai terminal.

| Nilai terminal | Arti |
|---|---|
| `completed` | Seluruh komponen yang direncanakan berhasil |
| `partial` | Bagian deterministik tersedia, komponen lain tidak. Bukan kegagalan dan bukan sukses penuh |
| `failed` | Run tidak menghasilkan laporan yang dapat dipakai |
| `cancelled` | Run dihentikan sebelum selesai |

Stage `simulating` dapat dikeluarkan dari rencana ketika deployment tidak memiliki adapter agent sama sekali. Stage yang dikeluarkan dilaporkan sebagai skipped, bukan dihitung sebagai pekerjaan yang selesai, sehingga persentase progres tidak menggambarkan pekerjaan yang tidak pernah terjadi.

### SSE dan fallback polling

Endpoint event analysis mengirim event bernama `status`. Setiap transisi disimpan ke PostgreSQL sebelum dipublikasikan; Redis hanya transport.

```text
id: 4
event: status
data: {"schema_version":"analysis-event-v1","event_id":"4","status":"simulating",
       "current_stage":"simulating","completed_stages":["queued","collecting_evidence",
       "building_context"],"skipped_stages":[],"percent":45,
       "message":"Panel persona sedang mengevaluasi skenario","warnings":[],
       "failure_code":null,"correlation_id":"...","occurred_at":"2026-08-15T08:01:20Z"}
```

Aturan client:

- simpan `event_id` terakhir dan kirim sebagai `Last-Event-ID` saat menyambung kembali; server melanjutkan dari sequence berikutnya tanpa mengulang event lama;
- `event_id` meningkat monotonik per analysis;
- `failure_code` bernilai `null` pada run normal dan membawa kode aman pada kegagalan terminal;
- jangan menebak penyebab kegagalan dari urutan `warnings`;
- bila stream berulang kali terputus, ambil snapshot status resource setiap tiga detik. Snapshot membaca state terbaru secara langsung, jadi ia tidak perlu dibandingkan dengan `event_id`.

Persentase progres berasal dari weighted stage completion yang dikirim backend. Client tidak menghitungnya sendiri.

## Idempotensi

| Operasi | Mekanisme |
|---|---|
| Membuat analysis | Header `Idempotency-Key`, unik per user |
| Membuat transaksi | `client_reference` opsional, unik per usaha ketika terisi |
| Konfirmasi receipt import | Konfirmasi ulang mengembalikan transaksi yang sama |
| Membuat export | Idempotency key pada pembuatan artifact |

Tujuannya sama di semua kasus: permintaan yang terkirim dua kali karena klik ganda, reconnect, atau retry jaringan tidak boleh menghasilkan dua record.

## Bentuk error

```json
{
  "error": {
    "code": "ANALYSIS_INPUT_INCOMPLETE",
    "message": "Data biaya variabel diperlukan untuk menghitung BEP.",
    "fields": [{"path": "pricing.variable_cost_per_unit_idr", "reason": "required"}],
    "correlation_id": "uuid",
    "retryable": false
  }
}
```

| Field | Fungsi |
|---|---|
| `code` | Kode stabil yang dapat dibaca mesin |
| `message` | Pesan berbahasa Indonesia yang aman ditampilkan |
| `fields` | Detail per field bila kesalahan bersifat validasi |
| `correlation_id` | Penghubung ke log dan trace saat pengguna melapor |
| `retryable` | Menentukan apakah tombol coba lagi masuk akal |

Respons error tidak pernah memuat stack trace, prompt, atau respons provider mentah. `409 EDUCATION_PREREQUISITE_NOT_MET` menyatakan modul wajib belum selesai, bukan kegagalan server.

Status `partial` adalah hasil yang sah, bukan error. Client menampilkan warning dan limitation dari server tanpa mengisi nilai yang hilang atau mengubahnya menjadi sukses.
