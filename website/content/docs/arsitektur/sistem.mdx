Arsitektur memisahkan fakta, simulasi, perhitungan, dan narasi. Pemisahan itu membuat hasil dapat diuji dan membuat kegagalan AI tidak menjatuhkan seluruh sistem.

Browser memanggil frontend, frontend meneruskan ke API melalui proxy server-side, dan API menyimpan state ke PostgreSQL sambil mengirim pekerjaan berat ke worker melalui Redis. Worker adalah satu-satunya komponen yang berbicara dengan evidence provider, OCR, dan provider LLM.

## Tanggung jawab komponen

| Komponen | Tanggung jawab | Yang tidak dilakukan |
|---|---|---|
| Next.js frontend | Input, route guard, status job, rendering hasil | Menghitung skor, uang, atau agregat |
| FastAPI | Authentication, validation, authorisation, use case API | Menjalankan simulasi atau OCR di request thread |
| Celery worker | Analysis, OASIS, OCR, PDF, recovery, retention | Menjadi tempat kebenaran state |
| Celery beat | Menjadwalkan rekonsiliasi run dan retention artifact | Mengubah hasil run |
| PostgreSQL | System of record identity, usaha, transaksi, evidence, analysis, event, metadata artifact | |
| Redis | Broker Celery dan transport event | Menyimpan report final |
| Object storage | Foto struk dan PDF privat dengan signed URL | Menyimpan object publik permanen |
| OCR | Mengubah gambar struk menjadi draft berconfidence | Membuat transaksi final |
| Provider LLM | Menjalankan agent melalui adapter CAMEL | Menghasilkan angka otoritatif |

Frontend memanggil backend melalui route proxy server-side, sehingga browser memakai path API same-origin dan credential provider tidak pernah sampai ke bundle klien.

## Alur Market Analysis

1. API memvalidasi input, prerequisite edukasi, dan idempotency key.
2. API menyimpan run `queued` beserta snapshot input yang immutable, melakukan commit, lalu mengirim task.
3. Worker mengumpulkan evidence snapshot. Setiap field membawa source, waktu observasi, dan quality.
4. Orchestrator membangun konteks terstruktur dan menjalankan empat council.
5. Engine deterministik menghitung finance dari typed input, lalu scoring memakai rule versioned.
6. Report council menyusun narasi hanya dari artifact yang sudah divalidasi.
7. Validator memeriksa schema, kutipan, dan konsistensi aritmetika.
8. Run menjadi `completed`, `partial`, `failed`, atau `cancelled`.

State disimpan ke PostgreSQL sebelum event dipublikasikan melalui Redis. Urutan ini yang membuat polling snapshot selalu menjadi rujukan yang sah ketika SSE terputus.

Urutan stage bersifat linear. Cabang `building_context -> calculating_finance` dipakai ketika deployment tidak memiliki adapter agent sama sekali, sehingga stage `simulating` dikeluarkan dari rencana dan dilaporkan sebagai skipped, bukan dihitung sebagai pekerjaan yang selesai. Tiga keadaan terminal pertama ditentukan pada `validating_report`; `cancelled` melengkapi state machine untuk run yang berhenti sebelum selesai, dan diagram menampilkan dua contoh titik keluarnya.

Setiap run menyimpan snapshot input, snapshot evidence, correlation ID, informasi idempotency, model manifest, prompt manifest, cohort, seed, budget, dan artifact agent.

## Alur foto struk

```text
created -> uploading -> queued -> preprocessing -> extracting
  -> ready_for_review -> confirmed -> committed
  | failed | cancelled
```

Upload berjalan langsung dari browser ke object storage melalui signed URL, sehingga file besar tidak melewati API. OCR dijalankan worker pada queue terpisah agar gambar besar tidak menahan permintaan transaksi biasa.

## Pembagian penyimpanan

- **PostgreSQL** adalah system of record. Uang disimpan sebagai integer rupiah, waktu disimpan dalam UTC, dan identifier berupa UUID tanpa makna bisnis.
- **Redis** menyimpan queue dan transport event jangka pendek. Job yang hilang direkonsiliasi dari state PostgreSQL, bukan dari Redis.
- **Object storage** menyimpan foto struk dan PDF export sebagai object privat.
- **Trace OASIS** ditulis per run ke direktori unik, diregistrasikan sebagai artifact, lalu dihapus melalui retention job yang eksplisit. Tidak ada file trace global yang ditimpa antar-run.

## Ketahanan sistem

- Idempotency key mencegah analysis, transaksi, dan export ganda.
- Recovery lease mencegah task yang masih hidup diambil worker lain terlalu awal, sekaligus memungkinkan run yang worker-nya mati dikembalikan ke antrean.
- Timeout terpisah per provider data dan per panggilan LLM.
- Retry hanya untuk error transient. Error schema atau policy tidak diulang tanpa perubahan.
- Budget keras per run untuk jumlah persona, round, concurrency, token, dan wall clock.
- Fallback deterministik ketika OASIS gagal, dengan hasil berstatus `partial`.
- SSE dapat dilanjutkan dengan `Last-Event-ID`; polling snapshot menjadi cadangan.
- Correlation ID mengalir dari API ke Celery, trace OASIS, hingga laporan dan log.

## Batas antar repository

Frontend, backend, dan dokumentasi adalah tiga repository terpisah tanpa import lintas direktori. Kontrak di antara mereka adalah HTTP API dan skema OpenAPI, bukan modul bersama. Rincian struktur kode ada pada [Struktur kode dan standar](/docs/engineering/struktur-dan-standar).
