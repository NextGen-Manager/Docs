Website dokumentasi dan frontend dapat dibangun sebagai dua proyek Vercel terpisah. Backend bukan satu fungsi stateless: API, Celery worker, Celery beat, PostgreSQL, Redis, private object storage, dan volume trace mempunyai lifecycle serta kebutuhan operasional yang berbeda.

## Website dokumentasi

Buat proyek Vercel dari repository `Docs` dengan Root Directory `website`. Gunakan framework preset Next.js dan domain `simumarket-docs.vercel.app`.

Build settings:

```text
Install Command: npm install
Build Command: npm run build
Output: Next.js default
```

Website tidak membutuhkan secret runtime. Snapshot `openapi/simumarket-v1.json` dibundel saat build dan playground publik dinonaktifkan. Setelah kontrak backend berubah, ekspor snapshot baru, jalankan `npm run docs:generate`, lalu verifikasi parity serta build sebelum deploy.

## Frontend dan backend

Frontend memanggil backend melalui proxy server-side dan tidak mengekspos credential provider. Environment produksi membutuhkan origin HTTPS yang eksplisit pada CORS, cookie `Secure`, secret JWT unik, serta URL backend yang benar.

Backend minimum terdiri dari:

```text
Internet
  -> frontend
  -> API
     -> PostgreSQL
     -> Redis -> worker dan beat
     -> private object storage
     -> provider eksternal dari worker
```

API dan worker harus memakai revision aplikasi yang sama. Migration dijalankan satu kali sebelum traffic memakai schema baru. Worker analysis dan artifact menggunakan queue terpisah agar OCR atau PDF tidak menahan request API.

## Secret dan data privat

- Simpan JWT secret, provider key, dan object-storage credential di secret manager platform.
- Jangan menaruh secret pada variable `NEXT_PUBLIC_*`, repository, image, log, atau dokumentasi.
- Bucket receipt dan export bersifat privat; akses browser hanya melalui signed URL berumur pendek.
- OASIS trace dan foto struk mempunyai retention job serta tidak boleh ikut backup publik.

## Health dan observability

`GET /v1/health` memeriksa proses API. `GET /v1/ready` dipakai readiness check untuk dependency penting. Pantau queue depth, umur job tertua, lease recovery, failure code, OCR latency, provider usage, dan penghapusan retention.

Correlation ID mengikuti request, event, task, dan log. Log tidak memuat cookie, raw receipt text, free-form user note, signed URL lengkap, atau prompt payload sensitif.

## Pemeriksaan setelah deploy

1. Buka dokumentasi pada kedua locale dan uji language switch.
2. Uji register, login, refresh, dan logout dengan cookie production.
3. Jalankan analysis dan periksa status, hasil, serta warning yang ditampilkan.
4. Uji reconnect SSE dengan `Last-Event-ID`.
5. Upload fixture struk non-pribadi, review draft, confirm sekali, dan periksa idempotency.
6. Buat PDF, unduh melalui signed URL, lalu pastikan expiry dan tenant isolation bekerja.

Rujukan platform: [Vercel untuk Next.js](https://vercel.com/docs/frameworks/full-stack/nextjs) dan [deployment Fumadocs](https://www.fumadocs.dev/docs/ui/deploying).
