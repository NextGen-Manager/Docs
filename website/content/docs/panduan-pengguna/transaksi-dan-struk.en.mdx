title: Products, transactions, and receipt photos
description: Record sales manually or through a reviewed OCR draft.

Transaction Management uses one product catalogue and one final transaction representation. Manual, batch, and receipt-photo inputs must end as backend-validated transaction records.

## Preparing products

An owner creates products with a name, selling price, and permitted cost data. A cashier can read active products and their selling prices to record sales, but cannot inspect cost, margin, or modify products.

## Manual transactions

1. Select the business and products.
2. Enter quantities, time, and channel.
3. Confirm the transaction.
4. The backend calculates `line_total_idr` and `gross_total_idr`.

The frontend is not the authoritative money calculator. A `client_reference` can make network retries idempotent within one business.

## Importing a receipt photo

1. Select a business and a JPEG or PNG file.
2. The browser calculates SHA-256 and requests a signed upload URL.
3. The file is uploaded directly to private object storage.
4. The backend verifies magic bytes, size, checksum, pixel limits, and image decoding. EXIF metadata is removed during sanitisation.
5. A worker runs preprocessing and PaddleOCR.
6. The user compares the image with the draft, corrects fields, and matches every item to a product.
7. If the line-item sum differs from the receipt total, the user must explicitly accept the mismatch.
8. Confirmation creates the transaction once in an atomic database transaction.

OCR never creates a final transaction without human review. Idempotent confirmation returns the same transaction when repeated.

## Analytics

Analytics becomes `available` only after transactions span seven distinct local dates. Before that, the status is `collecting` and aggregate lists remain empty. Products without minimum exposure are not selected as the bottom product.

Every insight includes an observation window, the `Asia/Jakarta` timezone, a `rule_version`, and limitations. Low volume alone is not enough to recommend removing a product.

## Exports

An owner can request an analysis-report PDF or transaction-summary PDF. The job runs asynchronously. Downloads use short-lived signed URLs, and artifacts follow the retention policy.

OCR reference: [PP-StructureV3](https://www.paddleocr.ai/latest/en/version3.x/pipeline_usage/PP-StructureV3.html). Using this engine does not replace calibration against an Indonesian MSME receipt dataset.
