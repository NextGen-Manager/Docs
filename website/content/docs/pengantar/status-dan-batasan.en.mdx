This page is **the only place implementation status is recorded**. Other pages explain how things work and how they are designed without repeating status markers, so no two places can contradict each other when something changes.

| Status | Meaning |
|---|---|
| Available | In the product with verification |
| Limited | Usable, subject to the restriction stated on that row |
| Planned | The design is settled in the technical documents, not yet in the product |
| Unvalidated | Operational, but its parameters or quality are not expert-validated |

## What `partial` means

`partial` means the valid deterministic parts can still be shown while another component is unavailable. The failed part stays in the report with a safe reason and stays in the table of contents.

What the system does not do when a run is `partial`:

- assign default values to the failed component;
- shift the weight of an unscorable dimension onto other dimensions;
- relabel the run as `completed` for a tidier presentation.

The full explanation is in [Data sources, finance, and scoring](/en/docs/arsitektur/evidence-finance-dan-scoring).

## Limits on simulation results

Synthetic personas help test reactions to a scenario in a structured way. The output is not a statistical representation of the population of Greater Jakarta and does not replace interviews, observation, or direct market evidence. Every persona quote is labelled a synthetic response and never uses a real person's name.
